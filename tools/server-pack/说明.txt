DIE_Reborn 服务器包 (Windows Server, 阿里云 ECS)
==============================================

本包自带 .NET 运行时和游戏数据, 服务器上不用装 .NET、不用装游戏、不用装 Steam。

服务器公网地址: {PUBLIC_HOST}   (写在 DIE_Server\public-host.txt)

一、阿里云安全组 (只做一次, 在阿里云网页控制台里)
----------------------------------------------
实例详情 -> 安全组 -> 配置规则 -> 入方向 -> 手动添加, 加四条:

  协议   端口范围          授权对象
  TCP    1555/1555         0.0.0.0/0     (大厅: 登录 / 菜单 / 商店)
  TCP    2555/2555         0.0.0.0/0     (匹配 / 开局)
  TCP    8555/8555         0.0.0.0/0     (登陆器: 服务器列表 / 在线人数 / 补丁镜像, 只读)
  UDP    50000/50099       0.0.0.0/0     (战斗服, 每局占一个)

远程桌面用的 TCP 3389 应该已经有了, 别删。

二、放到服务器上 (只做一次)
------------------------
1. 远程桌面连上服务器, 把整个 DIE_Server 文件夹复制过去, 比如 C:\DIE_Server。
   (路径里最好别有中文)
2. 防火墙: 第一次打开「DIE-ServerConsole.exe」(服务器控制台) 时它会自己检查并放行, 弹出管理员确认点"是"。
   不用控制台的话, 右键「开放防火墙.cmd」-> 以管理员身份运行。

三、开服 (推荐用服务器控制台)
------------------------
双击 DIE_Server 里的「DIE-ServerConsole.exe」, 点「开服」。控制台里能看到:
  - 三层各有多少人: 大厅 (TCP 1555) / 匹配排队 (TCP 2555) / 战斗服 (UDP, 每局一个)
  - 每一局的模式、地图、人数、负载; 每个玩家在哪 (大厅 / 排队 / 哪一局)、Steam ID
  - 服务器进程和整机的 CPU / 内存, 最近 30 分钟的曲线
  - 实时日志 (可按警告 / 错误筛选)
  - 「网络与端口」: 防火墙一键放行、请登记处从外网反连测端口、路由器 UPnP 映射
  - 「设置」: 服务器名称 / 位置 (改了立即生效)、公网地址 (可自动检测)、
    打开控制台自动开服、崩溃自动重启、每天自动备份账号库 (data\backups\, 留 30 份)
关掉控制台时可以选"服务器在后台继续运行", 再打开控制台会自动接上。

不用控制台也行: 双击「启动服务器.cmd」。窗口里依次出现这几行就是正常的:

  游戏数据已加载: C:\DIE_Server\gamedata
  Request 服务器已监听 0.0.0.0:1555
  匹配服务器已监听 0.0.0.0:2555
  服务器公网地址 {PUBLIC_HOST} -> {PUBLIC_HOST}
  已以匿名游戏服务器登录 Steam ...        (启动后几秒)

- 关掉窗口就是关服。远程桌面直接点右上角 X 断开没关系, 服务器照跑;
  但别在服务器上"注销", 那会把它一起关掉。
- 玩家登录时窗口里会出现 "Steam 核验通过 SteamID ..."。

四、客户端
--------
玩家用登陆器连进来: https://github.com/spardanviro/DIElauncher
开服后这台服务器会自动出现在每个玩家登陆器的"服务器"列表里 (名字、位置、延迟、人数),
玩家点选它再点「开始游戏」即可, 不用发任何文件给玩家。

- 列表里的名字和位置在控制台「设置」里改 (立即生效); 或者直接改 DIE_Server\server-info.txt 再重启。
- 开服约一分钟后日志里出现"已在登记处登记"就说明上了列表。出现"登记没成功"的话,
  多半是 8555 端口没对公网开放 (登记处要反过来连一下确认)。
- 不想上列表: server-info.txt 里写 listed=no。这时玩家要在 DIE-Launcher.exe 旁边放一个
  launcher.json, 内容是 { "serverHost": "{PUBLIC_HOST}" }。

五、数据和日志
------------
DIE_Server\data\die_reborn.db     所有账号 (进度、背包、货币)。备份它 = 备份全部账号。
DIE_Server\logs\                  服务器日志, 按天一个文件。出问题先看当天的那个。

六、以后更新服务器
----------------
1. 关服 (控制台点「停服」, 再关掉控制台)。
2. 用新包里的 DIE_Server 覆盖服务器上的文件夹。
   新包里没有 die_reborn.db, 覆盖不会动到账号 —— 但保险起见, 覆盖前先备份 data\die_reborn.db。
3. 重新开服。

六点五、把本机账号进度搬到服务器上
------------------------------
(只有打包时加了 -ImportLocalAccounts 参数, DIE_Server\import\ 里才有 die_reborn.db;
 普通的「打包服务器.cmd」不带)
1. 关服。
2. 双击「导入本机账号.cmd」: 先预演列出要导入的账号 -> 输入 Y 确认 -> 自动备份 data\die_reborn.db 后导入。
   按 Steam ID 对人: 服务器上已有的这个人, 进度换成本机的; 没有的新建; 其他玩家不动。
3. 开服。

七、注意
------
- 公网 IP: 现在的 {PUBLIC_HOST} 是实例自带的公网 IP。按量付费实例如果"节省停机",
  公网 IP 可能被回收, 再开机就变了。建议在实例页面点「转换为弹性公网 IP」固定下来;
  真变了就改 public-host.txt 并让大家改 launcher.json 里的地址。
- 流量: 带宽按使用流量计费, 这游戏一局的流量很小, 几个人玩费用很低。
- 服务器要能连上 Steam (核验玩家身份用)。开服几秒后没出现"已以匿名游戏服务器登录 Steam",
  检查服务器的出站网络, 再看 logs\ 里当天的日志。
